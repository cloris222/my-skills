### 3.2 唯一相關的線索：`IntakeInit.riskRemarks`

`POST /IntakeInit` 的回應有一個欄位 `riskRemarks`。以下是 `CallCenter_postman_req_res.txt` 中 01-1 的實測紀錄，`riskRemarks` 的值為 `null`：

```json
// POST /api/v1/CallCenter/IntakeInit
// Request
{ "agentId": "A0001", "contactId": "test-contact-001", "callerTelNo": "0212345678" }
// Response
{
  "status": 0,
  "msg": "SUCCESS",
  "data": {
    "customerType": 1,
    "telNoWithZero": "0212345678",
    "riskRemarks": null
  }
}
```

前端**只從命名推測**，`riskRemarks` 可能就是舊系統 `queryRiskRemark` 併入進線初始化後的結果。Delivery 3 的 `types/callCenter.ts` 與 `CallCenter_Frontend_AI_Prompt.md` 都沒有提到這個欄位，前端無法確定它的用途，也無法確定 `null` 代表什麼。

即使推測正確，前端認為它不符合 §4 情境的理由是：

1. **查詢對象**：`IntakeInit` 的 request 只帶入 `callerTelNo`（發話號碼）。受話號碼是值機員之後才手動輸入的，進線初始化時還不存在。
2. **時機**：`IntakeInit` 只在進線時呼叫一次，值機員之後修改發話號碼時，無法藉此重新查詢。

如果前端的理解有誤，請在 §6 Q6 說明。

## 4. 前端使用情境

呼叫位置：`src/pages/intake/IntakeForm.vue`

```text
值機員在「發話號碼／受話號碼」任一欄位輸入後離開（change 事件）
  │
  ├─ 欄位為空白 ──→ 清空衍生欄位、提示必填，不查風險名單
  │
  └─ 呼叫號碼解析，取得 areaCode（區碼）／ telNo（號碼）
       │
       ├─ 解析失敗 ──→ 顯示錯誤訊息，不查風險名單
       │
       └─ 解析成功且號碼非空 ──→ 查詢風險名單
            │
            ├─ 命中     ──→ 通知顯示註記訊息（標題「風險名單註記」）
            ├─ 未命中   ──→ 不顯示任何東西
            └─ 查詢失敗 ──→ 處理方式待確認（§6 Q5）
```

使用情境的幾個特性，供後端判斷時參考：

- **呼叫頻率**：一通電話最多查 2 個號碼，值機員每修改一次號碼就會重查一次。同一號碼可能被重複查詢。
- **等待方式**：查詢期間畫面會顯示全螢幕 loading 遮罩，值機員要等查詢結束才能繼續操作。
- **號碼來源**：前端的號碼是「區碼＋號碼」兩個欄位分開存放。後端需要哪種格式（合併、分開、要不要補 0）都可以配合。

目前的 mock 實作（串接完成後會替換掉）：

- `src/pages/intake/mocks/checkRiskMock.ts`：固定回傳命中，訊息即 §2.2 的範例
- `IntakeForm.vue` 的 `checkPhoneRisk()`：呼叫上述 mock，命中時顯示通知

> 前端已知待修：`checkPhoneRisk()` 目前傳入的是號碼解析後的「號碼」欄位，**不含區碼**。例如 `0212345678` 會被解析為區碼 `02`、號碼 `12345678`，只有 `12345678` 被傳入。串接時，前端會依後端要求的格式調整，後端不必遷就目前的寫法。
